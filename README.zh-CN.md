# CITES 贸易加工阶梯

**面向固定审查名额的 CITES 贸易审查候选排序：加工形态阶梯构造与学习排序流水线。**

作者：**廖彬** · 2026 年 10 月启动 · 最后更新 2026-11-01

English version: [README.md](README.md)

---

## 1. 这是什么

CITES 把合法野生动植物贸易记录成「物种 × 出口方 × 进口方 × term × 年份」。
审查机构每一轮只能把很少的案例送进深度审查，所以真正的问题不是「哪个单元风险最高」，
而是「先读哪几个单元」。

本仓库围绕这个约束做五件事：

1. 把年度记录聚合成「物种—出口方—进口方」单元；
2. 把 115 个 CITES term 映射到四级加工阶梯（S0 活体/整体 → S3 成品）；
3. 标注单元首次升到更高阶梯的年份，要求同一窗口内至少两条记录，挡掉单条噪声；
4. 用学习排序模型给单元排序，特征只使用测试年之前的信息；
5. 按年滚动评估，与纯贸易量、形态历史、随机期望三条基线对比。

重点不是提出新的排序算法，而是让**单元、标签、指标三者对齐审查动作**：
审查者只看前 `B` 个名字，训练和评价就都盯住前 `B` 个名字。

## 4. 方法

* **单元**：物种—出口方—进口方。
* **阶梯**：S0 活体/整体，S1 原料/初级分割，S2 半成品，S3 成品；
  `unspecified` 按缺失处理。
* **标签**：窗口内出现未被使用过、且高于历史最高阶梯的 S2/S3 形态，
  同一窗口至少 `K = 2` 条记录；敏感性分析取 `K = 1`、`K = 5`、`w = 2`。
* **模型**：LightGBM LambdaRank，300 棵树，学习率 0.05，叶数 31，
  特征与行采样均为 0.8。
* **查询块**：每年打乱后切成不超过 9,000 行的块；截断层级 30。
* **种子**：0、1、2，先按种子 z-score 再平均。
* **评估**：滚动起点 2017–2024（用 2016 … `T-1` 训练），
  名额 `B ∈ {20, 50, 100, 200, 500, 1000}`，指标 `Hit@B`、`Recall@B`、`Precision@B`。
* **基线**：近三年记录数、近三年 S2/S3 记录数、解析随机期望；
  平手用 `np.lexsort` 按总记录数决定。

## 5. 主要结果

八个测试年的均值：

| 名额 `B` | 模型 | 纯贸易量 | 形态历史 | 随机期望 | 召回率 | 精确率 |
|---|---|---|---|---|---|---|
| 100 | **8.6** | 0.8 | 4.0 | 0.10 | 9.5% | 8.6% |
| 1000 | **39.4** | 3.8 | 26.4 | 0.97 | 42.9% | 3.9% |

* 模型在 **8/8** 个测试年都高于纯贸易量基线。
* 同一个 LightGBM 把排序损失换成逐点二分类，`B=100` 的命中从 **7.6 掉到 0.2**（单种子）。
* 三种排序实现落在 **7.4–9.4**；逻辑回归为 4.5。
* 候选池当年阳性率 **0.097%**，所以 8.6% 的精确率约为随机抽取的 **89 倍**。
* 模型名单与纯贸易量名单几乎不重合：`B=100` 平均只重合 **1.4 个**单元，
  `B=1000` 重合 **35.5 个（3.5%）**。
* 消融中去掉形态组下降最大（7.6 → 4.4），但按年标准误为 2.05，只作方向性证据。

汇总数字在 `results/`；完整表格可由流水线重新生成。

## 8. 快速开始

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt

# 放入聚合表（或设置 CITES_DATA_DIR）：
#   data/links_l4.parquet
# 字段说明见 docs/DATA.md

python src/make_coverage.py
python src/run_main.py
python src/run_compare.py --part models --seeds 0
python src/run_compare.py --part ablation --seeds 0
python src/run_hparam.py
python src/run_robust.py
python src/run_shap.py

python src/make_figures.py
```

`run_main.py` 会写出逐年的切分文件，`run_robust.py`、`run_shap.py` 和部分图的子面板会复用它，
所以要先跑主实验。最慢的是特征构建；`cache/` 生成后，后续运行会复用。

## 9. 几点提醒

1. **两套口径。** 主结果是三种子平均；消融与模型对照是单种子，不能直接跨表比较。
2. **不同标签设置不能比命中。** `K=1` 每年 205 个阳性，`K=5` 是 30 个，`w=2` 是 166 个，
   主口径是 92 个；命中变高可能只是阳性变多，必须对照同口径基线。
3. **精确率要配基数看。** 8.6% 之所以不算低，是因为候选池里大约每一千个才有一个跃迁。
4. **平手很重要。** 贸易量是小整数、平手组很大；只用 `argsort` 会按文件行序决定名单。
5. **阶梯是构造出来的。** 因此单独发布为 CSV，读者可以替换后重跑。

## 10. 局限

* 只看得到合法、已报告的贸易。
* 评估是回溯性的，不是前瞻试验。
* 候选集要求近三年有记录；沉寂后重新出现的贸易流不在覆盖范围内。
* 用记录条数而非数量或重量，因为加工品的计量单位并不统一。
* 阶梯不是风险分数；跃迁是审查触发信号。
