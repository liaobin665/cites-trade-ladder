# CITES Trade Ladder

**Processing-form ladder construction and learning-to-rank pipeline for
prioritising CITES trade-review candidates under a fixed review budget.**

Author: **Liao Bin (廖彬)** · Started October 2026 · Last updated 2026-11-01

中文说明：[README.zh-CN.md](README.zh-CN.md)

---

## 1. What this is

CITES records legal wildlife trade as species × exporter × importer × term ×
year. A review body can only forward a small number of cases per cycle, so the
practical question is not "which unit is most at risk" but "which units should
be read first".

This repository builds that analysis:

1. aggregate annual records into species–exporter–importer units;
2. map the 115 CITES terms to a four-level processing ladder (S0 live/whole →
   S3 finished product);
3. label the year in which a unit first moves to a higher level, requiring at
   least two records to suppress one-off noise;
4. rank the units with a learning-to-rank model, using only information
   available before the test year;
5. evaluate the list year by year against volume, form-history and random
   baselines.

The contribution is alignment, not a new ranker: the **unit**, the **label** and
the **metric** all follow the reviewer's action of reading the first `B` names.

## 4. Method

* **Unit:** species–exporter–importer.
* **Ladder:** S0 live/whole, S1 raw/primary, S2 semi-processed, S3 finished;
  `unspecified` is treated as missing.
* **Label:** at least `K = 2` records of an unused S2/S3 form above the unit's
  historical best, inside a one-year window. Sensitivity: `K = 1`, `K = 5`,
  `w = 2`.
* **Model:** LightGBM LambdaRank, 300 trees, learning rate 0.05, 31 leaves,
  0.8 feature/row sampling.
* **Queries:** each year is shuffled and cut into blocks of at most 9,000 rows;
  truncation level 30.
* **Seeds:** 0, 1, 2; z-scored per seed and averaged.
* **Evaluation:** rolling origin 2017–2024 (train on 2016 … `T-1`), budgets
  `B ∈ {20, 50, 100, 200, 500, 1000}`, metrics `Hit@B`, `Recall@B`,
  `Precision@B`.
* **Baselines:** last-three-year record count, last-three-year S2/S3 record
  count, and the analytic random expectation. Ties are broken by total record
  count via `np.lexsort`.

## 5. Headline results

Eight test years, mean over years:

| Budget `B` | Model | Volume | Form history | Random | Recall | Precision |
|---|---|---|---|---|---|---|
| 100 | **8.6** | 0.8 | 4.0 | 0.10 | 9.5% | 8.6% |
| 1000 | **39.4** | 3.8 | 26.4 | 0.97 | 42.9% | 3.9% |

* The model beats the volume baseline in **8/8** years.
* Swapping the ranking loss for pointwise binary cross-entropy on the same
  LightGBM drops Hit@100 from **7.6 to 0.2** (single seed).
* Three ranking implementations land between **7.4 and 9.4**; logistic
  regression reaches 4.5.
* The candidate base rate is **0.097%**, so a precision of 8.6% is about
  **89×** chance.
* The model and volume lists are almost disjoint: **1.4 units** in common at
  `B = 100`, **35.5 (3.5%)** at `B = 1000`.
* Removing the form group is the largest ablation drop (7.6 → 4.4), but the
  per-year standard error is 2.05, so this is directional evidence.

Summary numbers are in `results/`; the full tables can be regenerated by the
pipeline.

## 8. Quick start

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt

# Put the aggregated table here (or set CITES_DATA_DIR):
#   data/links_l4.parquet
# See docs/DATA.md for the expected columns.

python src/make_coverage.py
python src/run_main.py
python src/run_compare.py --part models --seeds 0
python src/run_compare.py --part ablation --seeds 0
python src/run_hparam.py
python src/run_robust.py
python src/run_shap.py

python src/make_figures.py
```

`run_main.py` writes the per-year splits that `run_robust.py`, `run_shap.py`
and some figure panels reuse, so it must run first. Feature construction is the
slow part; once `cache/` exists, later runs reuse it.

## 9. Notes

1. **Two calibers.** Main results use three seeds; ablation and model
   comparison use one seed. They are not directly comparable.
2. **Label settings are not comparable.** `K = 1` gives 205 positives per year,
   `K = 5` gives 30, `w = 2` gives 166, against 92 for the main setting. Compare
   each with its own baseline.
3. **Precision needs a base rate.** 8.6% at `B = 100` is about 89 times a random
   draw because only ~1 candidate in 1,000 is a transition.
4. **Ties matter.** Volume is a small integer with large tie groups; a plain
   `argsort` would silently use file order.
5. **The ladder is a construct.** It is shipped as a CSV so it can be replaced;
   different mappings change the label count.

## 10. Limitations

* Only legal, reported trade is observed.
* The evaluation is retrospective, not a prospective trial.
* Units need recent activity to enter the pool; dormant-then-reappearing flows
  are not covered.
* Records are counted, not converted to quantities, because processed products
  do not use consistent units.
* The ladder is not a risk score; a transition is a review trigger.
